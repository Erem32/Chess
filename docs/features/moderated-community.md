# Optional community groups

The source suggests small moderated groups as an optional feature. They are not needed for lessons, computer practice, ordinary games or invitations, and can be left out of the initial university-project release.

If the team chooses to add them later, start with one simple opt-in group with a defined moderator and basic member/message permissions. Decide who can join, how unwanted contact is handled, and who reviews reports before exposing group communication. Keep group messages separate from game chat and respect each user's [contact preference](privacy-contact.md).

A developer can prototype the screen with local sample data independently. A real release needs a small backend data model and tests for joining, leaving and unauthorized access; it does not need a larger social platform.
